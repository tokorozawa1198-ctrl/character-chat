# 캐릭터 진행 저장 — 재접속 초기화 방지

- 저장은 현재 브라우저의 캐릭터별 localStorage에 있다. 프로필과 로그인 자체가 서버 진행 동기화를 제공하지는 않는다.
- 로드 effect에서 상태 setter를 호출한 직후 ref만 true로 바꾸면, 같은 렌더의 자동 저장 effect가 초기 Lv.1 / EXP 0을 먼저 기록한다. 실제 운영 빌드에서 기존 Lv.17 저장 앞에 Lv.1 쓰기가 발생하는 것을 재현했다.
- `loadedStorageKey`가 로드한 상태와 함께 다음 렌더에 반영된 뒤에만 저장한다. 현재 선택한 캐릭터의 키와 반드시 일치해야 한다. 로딩 중에는 EXP 지급과 초기화 관련 자동 effect도 대기한다.
- JSON 읽기 실패는 새 게임으로 취급하지 않는다. 기존 저장 문자열을 보존하고 재불러오기 안내를 표시한다. 저장 실패는 재시도 버튼을 표시한다.
- 시나리오 읽은 위치와 특별 보상 변경도 자동 저장 의존성에 포함한다.

검증: 최초 접속의 모든 쓰기에 원래 레벨 유지, 연속 새로고침, 세 캐릭터 전환, Chromium 프로세스 종료/재시작, Lv.3→4 획득 직후 종료/재시작, 손상된 JSON 원본 보존, 저장 용량 오류와 재시도. 이미 과거에 덮어써진 데이터의 복구를 이 수정이 보장하지는 않는다.

## 2026-10-10 — 오래된 탭의 덮어쓰기와 레벨 체크포인트

- 이전 수정에는 탭 사이 저장 충돌 방지가 없었다. 실제 브라우저에서 A/B 탭을 Lv.3 EXP 190으로 열고 B에서 시나리오에 진입해 Lv.4가 된 뒤 A로 돌아오면, A의 자동 저장이 Lv.3 EXP 190을 덮어쓰는 것을 재현했다. B를 다시 열어도 낮아진 레벨이 표시됐다.
- 현재 탭이 마지막으로 읽거나 쓴 전체 저장 문자열을 보관하고, 자동 저장 직전에 저장소의 최신 값과 비교한다. 다른 탭에서 바뀌었으면 오래된 상태를 쓰지 않고 최신 기록을 다시 불러온다. `storage`, `pageshow`, 포커스, 모바일 화면 복귀 때도 확인한다. 외부 저장을 로드한 직후에는 타임스탬프만 바뀌는 재저장을 생략해 탭 사이 무한 재저장을 막는다.
- 캐릭터마다 `${saveKey}_progress_v1`에 레벨·EXP 쌍을 작게 보관한다. EXP 획득 시 React 렌더를 기다리지 않고 저장하며 전체 저장을 불러올 때 더 진행된 값을 복원한다. 업데이트 전 코드가 남아 있는 탭이 전체 저장을 낮은 값으로 덮어써도 이 기록으로 레벨을 지킨다. 캐릭터별 진행은 서로 섞지 않는다.
- 레벨과 EXP 계산을 순수 함수로 분리하고 ref도 한 쌍으로 관리한다. React의 EXP state updater 안에서 레벨·보상·저장을 실행하지 않는다.
- 사용자가 명시적으로 새 게임 초기화/슬롯 불러오기를 할 때는 해당 체크포인트를 지워 의도한 낮은 레벨을 복원할 수 있게 한다. 현재 캐릭터 초기화는 현재 저장 키에 적용한다.
- 이 체크포인트가 없었던 과거의 덮어쓰기나 브라우저 데이터 전체 삭제에서 원래 레벨을 추정해 만들지는 않는다. 브라우저 저장 공간 자체에 접근할 수 없으면 기존 저장 실패 안내와 재시도가 계속 적용된다. 계정의 서버 동기화 기능을 새로 추가한 변경은 아니다.

추가 검증: `node tests/progressPersistence.test.cjs` 4개 통과, 운영 빌드 통과. Chromium 실제 두 탭 재현에서 레벨·EXP·시나리오 유지와 재저장 루프 없음, 프로세스 종료/재시작, 구버전의 Lv.1 덮어쓰기 복원, 전체 저장만 실패한 뒤 EXP 복원, 캐릭터 전환, 손상 JSON 보존, 명시적 슬롯 복원 및 전체 초기화를 모바일·PC 화면에서 확인했다.
